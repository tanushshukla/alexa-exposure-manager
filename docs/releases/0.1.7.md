# Alexa Exposure Manager 0.1.7

## Lossless Alexa migration

This release changes migration from a snapshot of currently known entities to
an exact, validated transfer of Home Assistant's native Alexa rules.

Alexa Exposure Manager now preserves all six filter sections:

- `include_entities`
- `include_domains`
- `include_entity_globs`
- `exclude_entities`
- `exclude_domains`
- `exclude_entity_globs`

The complete `entity_config` mapping is preserved as well. This includes Alexa
names, descriptions, display categories, unsupported entities with metadata,
and configured entity IDs that Home Assistant no longer knows.

Domain and glob rules are no longer flattened into the entities present during
migration. Rules for future entities, currently unmatched globs, source order,
and duplicate list entries remain in the managed YAML.

## Safer preview and import

Opening a migration preview changes neither managed files nor persisted
migration state. The preview shows an inventory of every source rule section so
the source can be checked before import.

Confirmation then:

1. Verifies that both managed-file revisions still match the preview.
2. Renders the complete filter and entity configuration.
3. Creates a backup and atomically replaces each managed file from a flushed
   temporary file.
4. Runs Home Assistant's full configuration validation.
5. Re-reads the files and verifies that their semantic model matches the source.
6. Restores both previous files if validation or verification fails.

A failed confirmation cannot be reused; create and review a fresh preview before
retrying.

## Rule-based filters

Filters containing domain rules, glob rules, or mixed include and exclude
sections are identified as **Rule-based**. The panel preserves those rules and
records later entity exposure changes as explicit entity exceptions.

An edit is rejected if it cannot represent the requested entity state without
changing the exposure of unrelated entities. The panel does not offer a
destructive conversion from a rule-based filter to a simple allowlist or
blocklist.

An entirely empty native filter retains Home Assistant's registry-default Alexa
exposure. Editing is disabled for this state because converting it implicitly
would change behavior. Fresh manager-owned files instead use a nonmatching
include glob, keeping new installations safely opt-in.

## Owner upgrade sequence

1. Take and verify a restorable full Home Assistant backup.
2. Leave the current inline Alexa `filter` and `entity_config` in place for one
   restart so Alexa Exposure Manager can capture them.
3. Install `0.1.7`, restart Home Assistant, and open Alexa Exposure Manager.
4. Select **Preview existing Alexa configuration**.
5. Review the entity counts and the six-section source inventory.
6. Confirm the import and inspect both managed YAML files.
7. Replace only the inline `filter` and `entity_config` mappings with the managed
   includes shown in the panel. Keep endpoints and credentials unchanged.
8. Run Home Assistant's configuration check and restart.
9. Confirm the panel reports that the active configuration matches the saved
   managed files, then run Alexa device discovery and test representative
   controls.

Keep the original Alexa YAML and full Home Assistant backup until discovery,
names, categories, and device controls have been verified.

## Compatibility

- Home Assistant `2026.6.4` or newer (tested through `2026.8.1`).
- HACS `2.0.5` or newer.
