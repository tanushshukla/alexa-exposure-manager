# Alexa Exposure Manager 0.1.6

## Fixed

This release repairs the recovery path for installations where:

- `configuration.yaml` contains `alexa: !include alexa.yaml`;
- `alexa.yaml` still contains a non-empty inline `smart_home.filter` or
  `smart_home.entity_config`;
- the two manager-owned files exist but contain safe empty defaults; and
- an earlier migration attempt was persisted as complete.

Previous releases trusted the stale completed state and skipped capturing the
inline rules. The panel therefore showed setup instructions with no migration
button, even though the old Alexa filter was still present.

On startup, `0.1.6` now detects that the completed state conflicts with the
empty managed files and non-empty inline rules. It captures the inline source
again and presents **Preview existing Alexa configuration**. The preview can
then be imported into the manager-owned files before changing `alexa.yaml` to
the managed includes.

The recovery screen also states that the managed files are intentionally empty
until this import is completed.

## Recovery sequence

1. Leave the current inline `filter` and `entity_config` rules in `alexa.yaml`.
2. Install `0.1.6` and restart Home Assistant.
3. Open Alexa Exposure Manager and select **Preview existing Alexa
   configuration**.
4. Review the counts, select **Import existing Alexa configuration**, and
   confirm.
5. Verify that `alexa_exposure_filter.yaml` and `alexa_entity_config.yaml` now
   contain the imported configuration.
6. Replace only the inline `filter` and `entity_config` mappings with the two
   managed includes shown in the panel. Keep endpoint and credential settings.
7. Run Home Assistant's configuration check and restart.

## Compatibility

- Home Assistant `2026.6.4` or newer (tested through `2026.8.1`).
- HACS `2.0.5` or newer.
