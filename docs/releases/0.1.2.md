# Alexa Exposure Manager 0.1.2

## Highlights

Migration correctness release. Three defects in the one-time import of an
existing manual Alexa filter are fixed.

- **Configured entity IDs are no longer discarded.** A hidden entity is recorded
  by its absence from `include_entities`, which erased configured IDs that Home
  Assistant no longer knows. Every stale ID from a legacy `exclude_entities`
  list was lost on import. Missing IDs are now retained in the entity
  configuration and stay visible until removed explicitly.
- **Entities Alexa cannot control are no longer imported.** Domains without a
  Home Assistant Alexa adapter, such as `select`, `calendar`, `conversation`,
  `notify`, `stt`, `tts`, `todo`, and `ai_task`, are counted as unsupported and
  skipped. Alexa metadata attached to them is preserved as hidden. A normal save
  already refused to expose these.
- **Migration reads the right configuration.** Activation repoints
  `alexa.smart_home.filter` and `entity_config` at the managed files, so the
  documented activate-then-migrate order flattened an empty filter. The
  integration now captures the Alexa configuration on every restart until
  activation and imports that copy.

## Added

- Migration refuses to import when the managed files changed after the legacy
  configuration was captured, so exposure saved through the panel is not
  overwritten.
- The migration preview reports which configuration it read and when that copy
  was captured.

## Compatibility

- Home Assistant `2026.6.4` or newer (tested through `2026.8.1`).
- HACS `2.0.5` or newer.

## Installation / upgrade

In HACS, open **Alexa Exposure Manager** and download `0.1.2`, then restart
Home Assistant and hard-refresh the browser.

## Upgrade notes

No configuration changes are required, and this release does not alter managed
files that already exist.

If you imported an existing filter on `0.1.1` or earlier, that import may have
dropped stale entity IDs and added entities Alexa cannot control. This release
prevents both, but does not clean up a file that already contains them, because
import stages changes over the current file rather than replacing it. To redo
the import cleanly:

1. Back up `alexa_exposure_filter.yaml` and `alexa_entity_config.yaml`.
2. Restore your original `filter` and `entity_config` inline in `alexa.yaml`,
   not as `!include`, so that migration can read them.
3. Delete both managed files from `/config`.
4. Restart. The integration recreates them empty and the panel offers migration.
5. Review the preview counts, then confirm.
6. Restore the managed `!include` lines, restart, validate, and run Alexa
   discovery.

## Verification

Backend and frontend suites pass, along with compatibility runs for Home
Assistant `2026.6.4`, `2026.7.4`, and `2026.8.1`, HACS validation, and Hassfest.
The owner-run Home Assistant OS pass with real devices remains the final release
gate and is not covered by automation.
