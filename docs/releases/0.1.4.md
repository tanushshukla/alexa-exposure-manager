# Alexa Exposure Manager 0.1.4

## Highlights

- **Alexa support detection is accurate again.** A runtime type-cast failure was
  being caught as an adapter error, which made every Home Assistant entity look
  unsupported. The panel now uses Home Assistant's Alexa adapter contract
  correctly and logs real adapter failures for diagnosis.
- **Existing Alexa YAML has a guided migration path.** The integration captures
  the inline `smart_home.filter` and `smart_home.entity_config` configuration
  before managed includes are activated, then offers preview and confirmation
  from both setup and configured states.
- **Deleted managed files recover safely.** If either managed include file is
  missing, the integration recreates only the missing file with an empty safe
  default. A surviving managed file is never overwritten during recovery.
- **The panel explains backup recovery.** Retry only re-reads the managed files;
  it cannot reconstruct deleted inline Alexa rules. If no captured source is
  available, restore those rules from a Home Assistant backup or start fresh.
- **Frontend upgrades no longer depend on a manual cache clear.** The custom
  panel module URL carries the integration version so Home Assistant loads the
  `0.1.4` bundle after restart.

## Compatibility

- Home Assistant `2026.6.4` or newer (tested through `2026.8.1`).
- HACS `2.0.5` or newer.

## Installation / upgrade

In HACS, open **Alexa Exposure Manager** and download `0.1.4`, then restart Home
Assistant. The versioned panel URL should load the new frontend automatically;
hard-refresh once if an already-open browser tab still shows the previous panel.

## Migration and recovery notes

For the safest migration, leave the old inline Alexa `filter` and
`entity_config` in place for one Home Assistant startup after installing this
release. Open the panel and confirm that a migration source was captured before
replacing those mappings with:

```yaml
smart_home:
  filter: !include alexa_exposure_filter.yaml
  entity_config: !include alexa_entity_config.yaml
```

Run Home Assistant's configuration check before restarting. After activation,
preview the captured configuration and confirm the import only if the counts
match your existing Alexa exposure choices.

If the old inline rules were already deleted and the panel reports that no
previous configuration was captured, exact exposure choices cannot be inferred
from Alexa's current device list. Restore the old YAML from a Home Assistant
backup and restart once so it can be captured, or continue from the empty safe
defaults and configure exposure again in the panel.
