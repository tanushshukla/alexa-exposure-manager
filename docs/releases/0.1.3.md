# Alexa Exposure Manager 0.1.3

## Highlights

- **The panel now reports why loading failed.** Home Assistant rejects WebSocket
  calls with a plain `{code, message}` object rather than an `Error`, so the
  panel stringified every load failure to `[object Object]` and hid the cause.
  The real message is now shown, in the main view and in the advanced tools.

This is a diagnostic fix. It does not change exposure behaviour, managed file
contents, or migration results.

## Compatibility

- Home Assistant `2026.6.4` or newer (tested through `2026.8.1`).
- HACS `2.0.5` or newer.

## Installation / upgrade

In HACS, open **Alexa Exposure Manager** and download `0.1.3`, then restart
Home Assistant and hard-refresh the browser.

## Upgrade notes

No configuration changes are required.

If the panel still reports that Alexa exposure data could not be loaded, the
message shown is now the reason. Check **Settings > System > Logs** and filter
for `alexa_exposure_manager` for the corresponding backend detail. A failure of
the Home Assistant WebSocket connection itself presents the same way, so confirm
that the rest of the interface is connected before treating the message as an
integration fault.

Remember that activation requires both managed includes. A configuration with
`filter: !include alexa_exposure_filter.yaml` but no matching `entity_config:`
line keeps the panel in setup-only mode.
